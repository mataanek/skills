# Health Data Extraction

This skill covers extracting health and workout data from consumer sources (Apple Health via Health Auto Export, Garmin Connect) and storing it in a structured format for training planning and feedback.

## Apple Health (Health Auto Export)
- See `scripts/health_extract.py` for the extraction script that reads daily JSON exports and appends to `~/ .hermes/wiki/personal/health.md`.
- The script preserves **all relevant detail** for training design: steps, resting HR, weight, HRV, sleep (total + deep), VO₂Max, active & basal energy, exercise minutes, and per-workout details (activity type, duration, distance, active energy, basal energy).
- Cron job `health_extract_morning` runs at 08:00 CET.

## Garmin Connect Historical Data Lake
- JSON exports are stored under `~/ .hermes/wiki/raw/garmin/`.
- Extraction script: `scripts/garmin_build_lake.py` builds a daily Parquet lake (`~/ .hermes/data/garmin_lake/daily.parquet`) with wellness, sleep, and run metrics.
- Trend analysis script: `scripts/garmin_trend.py` computes correlation between resting HR and high‑intensity run duration and appends a section to the personal health wiki.
- Reference: see `references/health_apple_garmin.md` for details on fields and schema.

## Notes
- Always validate that the source JSON files exist before parsing.
- For Garmin, high‑intensity runs are flagged by calories/min > 8 kcal/min OR Garmin trainingStatus in {PRODUCTIVE, PEAKING}.
- The lake is append‑only; re‑run the build script to incorporate new exports.
- **Pitfall**: Do not oversimplify workout data (e.g., aggregating to "1h of sport" loses the critical difference between walking and running). Preserve granular details like activity type, distance, and energy expenditure for meaningful correlation analysis.

## Description
Extracts and logs detailed daily health and workout data from Apple Health exports (e.g., generated by Health Auto Export) into a structured wiki for training planning and feedback. Per explicit user requirement: preserves EVERY available data point from the export files with zero data loss or summarization, as storage is not a concern. This includes all health metrics, all workout statistics, all activity types, and all temporal details. The output format maintains the granularity needed to distinguish between different workout types (e.g., walking vs running) and retain all available detail for deep causal analysis.

## Trigger Conditions
- Apple Health exports are generated daily at a known time (e.g., 23:00 CET) in a known directory.
- The exports consist of two JSON files per day: `health_export_*.json` and `workouts_export_*.json`.
- The user wants to maintain a historical log of health and workout data for training advice generation.

## Configuration
- Set the health directory path in the extraction script (default: `/mnt/c/Users/mataa/iCloudDrive/Documents/Personal/Health`).
- Ensure the wiki output directory exists (default: `~/.hermes/wiki/health.md`).
- Ensure the log directory exists (default: `~/.hermes/logs/health_extract.log`).

## Steps
1. **Identify latest exports**: Find the most recent `health_export_*.json` and `workouts_export_*.json` files in the health directory by modification time.
2. **Parse date**: Determine the target date (usually yesterday) from the file timestamps or export metadata.
3. **Extract health metrics**: From the health export, extract:
   - Steps (`stepCount`)
   - Resting heart rate (`restingHeartRate`)
   - Weight (`weight`)
   - Heart rate variability (`heartRateVariability`)
   - Sleep (total minutes and deep sleep from `sleepTime.stages.deep`)
   - VO₂Max (`vo2Max`)
   - Active energy (`activeCalories`)
   - Basal energy (`basalCalories`)
   - Exercise minutes (`exerciseMinutes`)
4. **Extract workout details**: From the workouts export, filter workouts whose `startDate` matches the target date, and for each workout capture:
   - Activity type (`activityType`)
   - Duration (`duration`)
   - Distance (`statistics.HKQuantityTypeIdentifierDistanceWalkingRunning.sum`)
   - Active energy (`statistics.HKQuantityTypeIdentifierActiveEnergyBurned.sum`)
   - Basal energy (`statistics.HKQuantityTypeIdentifierBasalEnergyBurned.sum`)
5. **Format output**: Write a markdown entry under a heading `## YYYY-MM-DD` with two subsections:
   - `### Health Metrics` – list each metric with value and units.
   - `### Workouts` – list each workout with activity type, duration, distance, and energy values.
6. **Deduplication**: Skip writing if an entry for the target date already exists in the wiki.
7. **Logging**: Log each run (success, skipped, errors) to a log file.

## Pitfalls
- **Missing exports**: If no health export file is found, the script logs and exits without modifying the wiki.
- **Duplicate entries**: The script checks for an existing heading for the target date to avoid duplicate logging.
- **Time zone mismatches**: The script uses the file's modification time to determine the date; ensure exports are generated at a consistent time.
- **JSON structure changes**: If the export format changes (e.g., new keys), the extraction may miss data; validate with a sample export.
- **File access**: The health directory must be accessible (e.g., via iCloud Drive on Windows mounted at `/mnt/c/...`).
