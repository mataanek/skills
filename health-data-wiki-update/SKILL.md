# Health Data Wiki Update

This skill extracts metrics from JSON export files (such as those generated by Health Auto Export on iPhone) and appends them to a wiki page with deduplication and logging.

## When to Use
When you have a directory that receives periodic JSON export files containing health metrics (e.g., daily at a fixed time) and you want to maintain a running log in a wiki without duplicating entries.

## Inputs
- `export_dir`: Directory containing JSON export files (e.g., `/mnt/c/Users/mataa/iCloudDrive/Documents/Personal/Health`)
- `wiki_file`: Path to the wiki file to update (e.g., `~/.hermes/wiki/health.md`)
- `log_file`: Path to the log file (e.g., `~/.hermes/logs/health_extract.log`)
- `date_field`: The date to extract (default: yesterday)
- `metrics`: List of metric keys to extract from each JSON (each key maps to an array of `{date, unit, value}`)

## Steps
1. Ensure `export_dir` exists and contains at least one JSON file matching pattern (e.g., `health_export_*.json`).
2. Identify the most recently modified export file.
3. Determine the target date (usually yesterday, but configurable).
4. Read the JSON file and extract the specified metrics for the target date.
5. Check if the target date already exists in the wiki file (by scanning lines for the date prefix).
6. If not present, format a line: `- DATE: Steps: <value>, Resting HR: <value> bpm, Weight: <value> kg` (adjust labels per metric).
7. Append the line to the wiki file.
8. Log the action (timestamp, file processed, date, metrics extracted) to the log file.
9. If already present, log a skip message.

## Pitfalls
- Ensure the JSON structure matches expected format: each metric key maps to an array of objects with `date`, `unit`, `value`.
- If the export file is malformed or empty, the script will log an error and exit.
- The wiki file must be writable; ensure the directory exists.
- Timezone considerations: the export timestamp may be in UTC; adjust date calculation accordingly.

## Verification
- After running, check the wiki file for the new entry.
- Check the log file for confirmation.
- Run the script a second time to ensure it does not duplicate entries.
